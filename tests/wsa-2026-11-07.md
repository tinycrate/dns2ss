# WSA functional test notes — 2026-11-07

Environment-specific record. The project README intentionally keeps these notes separate.

## Environment

- Windows Subsystem for Android, Android 13, x86_64.
- Test SS server under `adb shell` on `127.0.0.1:18388` (`aes-256-gcm`).
- Debug build with the debug-only `com.android.shell` VPN exclusion.
- Remote DNS target `8.8.8.8:53` for the tests; the shipped default is `127.0.0.1:53530`.
- Test client installed as a separate APK.

## Results

- **Fast**: system DNS worked; fake-resolver TCP/UDP failed by design; diagnostics listed the underlying resolver `172.29.144.1`; HTTPS 200; non-DNS NTP OK.
- **Strict**: fake-resolver UDP/TCP succeeded (port-53 capture and source forging); repeated same-socket DNS queries hit the cache at 0 ms; fresh-socket cold queries were ~2 ms after `socks5.pipeline` was enabled; HTTPS 200; NTP OK; SS server logs saw only DNS.
- **Full**: fake-resolver UDP/TCP succeeded; non-DNS NTP went through SOCKS; HTTPS 200; SS server logs saw both DNS and `example.com:443`.
- Diagnostics after a Strict run: `Cache: 2 entries, 8 hits, 2 misses`.
- Mode switches restarted the VPN cleanly and updated the landing status.
- Stop removed the VPN network and terminated the `sslocal` child process.
- Tile first-run auto-start was exercised by launching the app with the tile-start extra.

## Latency findings

- The original ~430 ms cold DNS latency was a first-UDP-association stall, not DNS/SS RTT.
- `socks5.pipeline: true` reduced cold queries to single-digit milliseconds.
- The shared DNS tunnel socket and TTL cache made repeated queries effectively immediate (0 ms measured).
- Strict direct UDP had a separate bug: the direct socket was bound to `127.0.0.1`, so NTP failed. Binding wildcard fixed it.

## Limitations from this test environment

- WSA reports no Quick Settings tile support (`check-support=false`), so the tile UI could not be runtime-tested here.
- An actual Wi-Fi/cellular transition cannot be simulated reliably in WSA; the restart path was exercised through mode changes.
- A real remote DNS service at `127.0.0.1:53530` was not available; tests used `8.8.8.8:53`.
- WSA behavior can differ from a physical phone, which remains the final acceptance device.
